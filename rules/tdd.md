# Test-Driven Development

Always use TDD when implementing code:

1. **Write failing tests first** — define expected behavior before writing implementation
2. **Implement to make tests pass** — write the minimum code needed to satisfy the tests
3. **Refactor** — clean up while keeping tests green

For multi-step tasks, state a brief plan with verification checkpoints:

```
1. [Step] → verify: [check]
2. [Step] → verify: [check]
```
